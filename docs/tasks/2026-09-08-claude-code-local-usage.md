# Локальная аналитика Claude Code

## Цель

Добавить в Codex Pulse отдельный локальный источник токенов, моделей и проектов Claude Code, включая Code-сеансы, запущенные из Claude Desktop.

## Результат для пользователя

После первой рабочей Claude Code-сессии в «Использование → Токены и стоимость» появляются токены Claude, модели и проекты. Claude Web по-прежнему отвечает за общие проценты лимитов и время сброса; одинаковая подписочная квота не дублируется как два разных лимита.

## Контекст

- Claude Desktop 1.49585.0 установлен в `/Applications/Claude.app` и содержит встроенный Claude Code 2.1.260.
- Официальная документация Claude Code указывает локальное хранение сессий в `~/.claude/projects/` по умолчанию; Pulse также проверяет Claude Desktop Code-session folders, но только если там появляются JSONL-метаданные. На этой машине реальных JSONL-сессий пока нет.
- Pulse не читает/не сохраняет тексты промптов или ответов. Нужны только служебные поля даты, модели, cwd и числового usage.

## Изменить

- Добавить сканер стандартных локальных Claude Code JSONL-сессий и Claude Desktop Code-session folders с кэшем неизменённых файлов.
- Объединить его снимок с существующей локальной аналитикой Codex, не заменяя Claude Web quota bridge.
- Уточнить подписи интерфейса: Claude Web не отдаёт токены, но Claude Code может давать их локально.
- Добавить тесты для моделей, проектов, токенов и исключения неизвестных/текстовых записей.

## Не трогать

- IndexedDB Claude Desktop, Chrome cookies, авторизацию, сетевые запросы к Claude, Claude Web Connector и публикацию.

## Проверить

- `Scripts/test.sh`.
- `Scripts/build-app.sh release native`.
- На пустом локальном источнике Claude не появляются фиктивные токены; при появлении JSONL-сессии агрегаты отображаются под Claude.

## Откат

Удалить сканер Claude Code и вернуть прежнее поведение: Claude Web показывает только лимиты и сбросы.
