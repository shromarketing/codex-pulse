# Исследование: мониторинг анонсов сбросов Codex

## Вывод

Для локальной первой версии Pulse подходит один ранний источник с проверяемой первоисточной ссылкой: публичная лента `@thsottiaux`. На 2026-09-08 relay отдаёт JSON с `author`, `content`, `published_at`, `external_id` и прямым `x.com` URL. В выдаче обнаружен реальный анонс banked reset. Это не официальный API X, поэтому интерфейс обязан называть relay и давать ссылку на оригинальный пост.

`status.openai.com` — официальный источник инцидентов, но не расписание reset. Он не должен генерировать уведомление «лимит скоро обновится».

### Повторная проверка 2026-09-08

Новые публичные проекты подтвердили, что полезная схема состоит из двух разных контуров, а не из множества слуховых источников:

1. **Ранний публичный сигнал:** посты `@thsottiaux`. `gvm1229/codex-reset-monitor` использует только этот источник через официальный X API, хранит `since_id`, дедуплицирует и переводит только строго разобранный момент в пользовательский часовой пояс. Его правило верное: если в посте нет точного момента, не изобретать час.
2. **Подтверждение для конкретного аккаунта:** `account/rateLimits/read` уже возвращает в Pulse `rateLimitResetCredits.availableCount`. Проекты `jordan-edai/codex-reset-watcher`, `maximpri/CodexResets` и `gooderno1/codex-usage-core` показывают banked resets отдельно от обычных недельных/5-часовых окон. Это полезнее, чем добавлять Reddit, форумы или ручные исторические индексы как источник push-уведомлений.

`liyoungc/codex-reset-index` остаётся хорошей исторической хронологией, но не live-источником. Dayclaw допускает мониторинг других площадок, но не даёт их достоверности; в Pulse они не добавляются.

## Разобранные реализации

- `thinkingjimmy/codex-reset-watchdog`: public relay + периодический запуск; полезны тихая первая синхронизация и дедупликация. Зависимость от Dayclaw не переносим как доверенную истину.
- `gvm1229/codex-reset-monitor`: официальный X API + детерминированный классификатор времени + хранение состояния; полезны строгие регулярные выражения и отсутствие LLM в решении об уведомлении. X API/Cloudflare не входят в первую версию.
- `liyoungc/codex-reset-index`: структурирует hard/banked reset и прямые ссылки, но его dataset исторический и ручной, не live-источник.

## Выбранные правила

1. Уведомлять только о новом посте от ожидаемого автора и только при явном сочетании reset с Codex/usage/rate/limit либо при `banked reset`.
2. Не выводить предсказанную точную дату, если в тексте есть лишь «end of day» или другой неточный срок.
3. Первую успешную загрузку пометить как baseline без push.
4. Хранить локально только ID уже виденных публичных постов и краткий статус последнего сигнала.
5. Подтверждение факта сброса остаётся за официальным App Server и существующей проверкой квоты.
6. В русской карточке показывать детерминированный краткий смысл, а сырой англоязычный пост оставлять только по ссылке на первоисточник.
7. Время в МСК выводить лишь для относительного срока или точного времени с явно указанным часовым поясом. `end of day` и похожие формулировки остаются неточным сроком.
