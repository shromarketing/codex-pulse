# Design QA

- source: `Resources/design-reference.png`
- implementation: Codex Pulse 0.5.0 candidate; prior 0.4.10 visual captures and performance captures are in `/private/tmp/codex-pulse-performance-audit/`
- combined comparison: `design-comparison.png`
- viewport: reference normalized to 1080x760; implementation captured at 1080x760
- review rounds: 24

## Visible review

- P0: none.
- P1: none after the second pass.
- P2: the implementation intentionally uses a normal native macOS window instead of the reference's composited desktop scene; live Claude stays hidden in Simple mode because no local Claude session exists.
- Preserved: graphite hierarchy, compact sidebar, teal/orange provider coding, quota ring, history surface, task-routing surface, settings density, and native window behavior.
- Verified interactions: live analytics load, overview, 7/30/90-day recalculation, usage timeline, selectable daily activity, day-to-history handoff, data-backed history filters, filter reset, Simple/Pro settings, RU/EN localization, floating-widget toggle, Compact-to-Focus expansion/collapse, refresh control, task routing, and navigation.
- Fixed in 0.3: duplicate compact-widget waveform, inert expand affordance, off-screen Focus expansion, false green Claude state, stale period cache reuse, and underpowered routing for a full website build.
- Fixed in 0.3.1: collapsed menu content caused by an unconstrained `ScrollView`; empty stretched-widget canvas; misleading expand state after manual resize; overly transparent large widget; and undersized restored Adaptive frames.
- Fixed in 0.3.2: ambiguous Calendar/Task Receipts copy; non-interactive day cells; unexplained blank filtered history; zero-result category clutter; missing selected-day handoff; and repeated daily aggregation that stalled the 90-day view.
- Fixed in 0.3.3: every 7/30/90-day click forced a new external cost scan, kept the global spinner active for more than 15 seconds in the measured build, and made otherwise-local analytics tabs feel blocked. Period selection now filters one cached 90-day snapshot in memory; scheduled refreshes are quiet, while first load and explicit refreshes keep honest progress feedback.
- Fixed in 0.4.0: keyword-only routing that treated numeric scale and external I/O as ordinary medium work. The live router now exposes AI/Local modes, source and confidence, a responsive result grid, and a staged plan. The 200-site/8-GB case was checked both locally and through a real structured Codex request; both chose Terra/high for planning and split batch execution from verification.
- Fixed in 0.4.1: ambiguous standalone reset durations in the menu and desktop widget; missing refresh access inside the widget; and a Focus-width pace row that truncated both the warning and forecast. Reset and predicted exhaustion now use distinct verbs, the refresh control is accessible in every layout, and the warning stacks cleanly at narrow widths.
- Fixed in 0.4.2: the Compact layout briefly lost the provider-supplied weekly reset while preserving only the pace forecast. A dedicated secondary reset line now stays visible above the warning, and the menu popover's icon-only refresh is a labeled, stateful action.
- Fixed in 0.4.3: the restored Adaptive frame could remain only 108 pt tall because width alone marked it usable, leaving the fourth Compact row under the rounded lower edge. Restore validation now requires both width and safe height; Compact is 138 pt tall, and flatter manual frames render Mini.
- Fixed in 0.4.4: the 0.4.3 threshold was too aggressive and replaced the familiar information-rich 490 × 108 pt panel with a nearly empty Mini. The saved wide frame is Compact again, with five-point outer spacing and eight-point vertical padding; Mini begins only below 100 pt.
- Implemented in 0.4.5: the default Compact preset is 320 × 138 pt instead of 360 × 138 pt. Focus and Expanded now keep the header fixed and place all detail content in a vertical `ScrollView`; usage and intelligence are no longer hidden by intermediate heights.
- Startup no longer waits for the full first provider/analytics refresh before creating the configured floating panel; the widget becomes available immediately and updates in place.
- Finalized in 0.4.8 after live feedback: AppKit close/miniaturize/zoom traffic lights are permanently hidden. The widget's own refresh, expand/collapse, and close controls stay continuously visible at the top right, avoiding duplicated window actions.
- Fixed in 0.4.9: `paceSummary` no longer shrinks its colored surface to intrinsic text width. The shared Focus/Expanded component expands before applying its background, so the health card matches the quota, metric, and chart column edges.
- Fixed in 0.4.10: the default Compact footprint is 260 × 138 pt. Legacy default 320/360 pt Adaptive frames migrate to Compact, while custom Adaptive frames remain user-owned.
- Implemented in 0.5.0: Claude Web is an explicit opt-in service with Web/OAuth/Auto sources, immediate connection testing, recoverable permission/session errors, and separate session, all-model weekly, and model-scoped meters in the dashboard, menu, and expanded widget. Compact keeps the Claude limiting percentage without adding another text row.
- Fixed in build 21: the popup localization no longer replaces the entire pairing section with a status string. The code field and Pair button remain visible, pairing codes are created on launch when needed, and a static regression test protects the structural popup IDs.
- Verified in build 22: the real Claude Max 5x session is paired through Pulse Connector. The live dashboard and Settings show current-session and all-model weekly windows with remaining, used, and reset semantics. A sanitized 24-hour cache survives relaunch, while cookies and chat content stay in Chrome. Compact shows both providers, Focus/Expanded expose every returned window through scrolling, and Fable/model rows appear only when Claude returns them.
- Fixed and verified in build 24: Focus/Expanded no longer place one aggregate pace card after the Claude list. Codex quota windows are immediately followed by a Codex-labelled warning, exhaustion forecast, and safe-today value; Claude windows (including live Fable) are immediately followed by an independent Claude-labelled healthy forecast and safe-today value. Compact names the limiting provider in its single priority line. The live 340 × 300 Focus panel was scrolled through both groups; header controls stayed fixed and the scroll position advanced from 0 to 0.84.
- Implemented and verified in build 25: Usage now opens in a provider-aware quota mode with separate Codex/Claude/Fable cards, percentage history, 7/30/90-day filtering, and per-provider pace. Exact token/cost analytics remain a separate mode and never fabricate Claude projects or token counts. History likewise separates project-token receipts from local quota events. Live accessibility QA exposed rounded provider countdown timestamps being misread as new reset periods; a 90-minute boundary tolerance and legacy-noise sanitizer now keep only real percentage movement, actual resets, and 30-minute heartbeat points.
- Fixed in build 26: the menu Overview no longer reads as one Codex quota section followed by an apparently global token chart and a secondary Claude appendix. Each connected provider is now one coherent group containing its quota windows, provider-specific pace state, safe-today value, and the most constrained window's remaining-percentage history. Exact token totals, model/project rankings, and the bar chart live under the explicit “Codex tokens” tab with an honest Claude Web data-boundary note.
- Fixed in build 27: the default menu-bar percentage preset no longer collapses providers into one anonymous minimum. It renders persistent compact icon-and-percentage pairs for Codex and Claude, shows an honest dash while either value is unavailable, reserves the full width before the delayed Claude Connector response, uses monospaced digits to prevent jitter, and exposes both provider names and values to accessibility instead of relying on color or position.
- Fixed in build 28: Compact and Mini no longer let the global limiting-provider heuristic silently replace Codex details with Claude. Both top indicators remain visible and act as explicit provider tabs; Codex is the transient default for every widget instance, the selected tab gains a restrained provider-tinted surface and name, and reset/pace/forecast copy is derived from that same provider. A disconnected Claude selection resolves safely back to Codex. Focus/Expanded intentionally retain both full provider groups for comparison.
- Verified on 2026-09-10: the Smart menu-bar preset keeps its pace glyph while rendering one fixed native `Text` label for both providers; the Percent preset uses the same inline waveform-and-sparkle pair. This avoids macOS retaining only the first nested SwiftUI status-item child, while matching the service symbols used throughout Pulse. Live post-relaunch data reached both providers; no browser credentials or chat content were accessed.

## Data-state review

- Codex card was captured from the live read-only `Codex App Server` source.
- The live response showed separate Codex and Codex Spark weekly buckets plus the ChatGPT Pro plan; no account email was retained.
- Menu Usage and widget Focus/Adaptive captures were inspected from the live signed application, not a SwiftUI preview.
- Usage cards loaded the live local 30-day aggregate without reading prompt bodies.
- Daily/history QA used live 7/30/90-day aggregates; accepted captures are `07-final-by-day-layout.png`, `09-final-history-all.png`, and `06-90-day-stress.png` in the audit folder.
- Performance QA compares the same live 7/30/90-day and tab sequence before and after the cache change; accepted captures and timing notes are stored in `/private/tmp/codex-pulse-performance-audit/`.
- The pure in-memory filter benchmark averaged 1.101 ms over 300 switches on a stress fixture of 200 projects × 90 days; live period/tab checks showed no busy indicator after the first data load.
- The configured two-minute background refresh advanced the live timestamp from 01:05 to 01:07 and restored the official Codex App Server source without exposing a busy indicator or leaving the current screen.
- Apple Command Line Tools 27.0 beta 5 is installed. Because its SwiftPM helper still omits the bundled Swift Testing macro/runtime discovery, `Scripts/test.sh` supplies the official local plugin path; 20 Swift Testing tests in 4 suites execute and pass. Both release architectures also compile successfully.
- Four geometry regressions cover the 320 × 138 pt Compact preset, Focus preset, the user's existing 490 × 108 pt frame, and a truly short Mini frame. The signed live 0.4.5 Compact was captured at the narrower preset with percentage, reset, pace, forecast, and controls visible without clipping. Its live Focus accessibility tree exposed a vertical scroll area containing metrics, top model, and top project under the fixed controls.
- The signed live 0.4.2 Compact widget was inspected at its actual desktop size: weekly reset, pace warning, exhaustion forecast, refresh, expand, and close controls remain visible together.
- The 0.4.1 widget refresh button was clicked in the signed live app and returned to its ready state. Accessibility exposed separate “Обновить данные” and expand/collapse actions, plus full reset/exhaustion descriptions. A live minimum-Focus capture exposed the final truncation issue; the accepted layout stacks the warning and forecast instead of competing in one row.
- The first live AI pass proved structured bilingual routing through the signed-in Codex session. The follow-up hybrid path shows the local guarded route immediately and uses Luna/low only to refine it; timeout or malformed output leaves the local result intact.
- Claude parser coverage uses a sanitized fixture matching the live Usage page shape. The user approved the legacy cookie attempt; CodexBar could not see the active Claude Chrome profile. The bundled connector now keeps cookies in Chrome and has parser/pairing coverage, but still needs a live same-profile smoke test.

final result: passed — 44 Swift tests in 9 suites plus the popup/parser regression pass; the native release build and locally installed app pass strict code-sign verification. The rebuilt single-text menu-bar label and relaunched app returned live Codex and Claude quota snapshots. Public distribution still separately requires onboarding, Developer ID signing, notarization, and an update channel.
